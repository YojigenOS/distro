# 记录：第一次从仓库装出一台系统

**2026-10-20。** 在这之前，"系统"只存在于真机那张盘上（见
`记录-第一次装到真机.md`，那是 DD 进去的）。这一次是**从 `repo.os.yojigen.cn`
装出来的** —— 而且装成之后那些工具**真的在跑**。

## 做了什么

在一个空的 `alpine` 容器里，只用我们的仓库装 `minimal` 风味的直接包：

```sh
docker run --rm -v "$PWD/keys:/keys:ro" -e "PKGS=$PKGS" alpine:latest sh -c '
  mkdir -p /newroot/etc/apk/keys
  cp /keys/*.rsa.pub /newroot/etc/apk/keys/
  echo "https://repo.os.yojigen.cn" > /newroot/etc/apk/repositories
  apk add --keys-dir /newroot/etc/apk/keys --root /newroot --initdb $PKGS
'
```

★ **没有 `--allow-untrusted`** —— 签名是真的验的。

**`ps` / `procps` 第一次报错**，而那不是包的问题：

```
Error, do this: mount -t proc proc /proc
```

`chroot` 里没挂 `/proc`。挂上之后全对。**记下来是因为它很容易被误读成
"procps 装坏了"。**

## 而它顺带证明了一件更大的事

**这台系统是"装出来的"，不是"做出来的"。** 那意味着：

* 仓库里的包是自洽的（依赖能解析、签名能验、`apk` 能装）
* `minimal` 那个风味定义是完整的（46 个直接包就够装出一台能用的机器）
* 而那两个"失败"是宿主环境的限制，不是产物的问题

## 它和真机那张盘的关系

真机（`TX`）上现在有 33 个包，而它缺的 23 个正好是这批工具：

```
bc bzip2 chrony cpio cronie curl file iproute2 iputils less logrotate
lsof procps readline rsync shadow strace sudo tmux tzdata vim which zstd
```

★★ **所以不用重做盘。** `apk upgrade` + 装上那 23 个就够了 —— 那比 DD
一张新盘快得多，而它能反复做。

★ 而这件事本身值得记：**"更新一台已有的系统"和"造一张新的盘"是两个不同的
操作，而之前默认了后者。** 前者更接近用户真实的处境。

不是只写在这里 —— 同一套包装到了真机上，而它成功。

### 一个还没换掉的东西

`readline` 装上去的是 `8.3-r1` —— **就是那个没链 `libncursesw` 的坏版本**
（2026-10-20 修了配方，但新的还没建出来，见 `packages` 的提交 `7d45d87`）。

★ 而它现在**不影响任何东西** —— 而那件事我【量过】，不是推的：

    装好的系统（minimal，65 包）里：

      bash                NEEDED: libncursesw.so.6 · libc.so.6 · ld-linux
                          自己定义的 rl_* 符号: 382 个 · 未定义的: 0 个
                          → 【静态链了 readline】，而且它【自己】链了 ncursesw

      libreadline.so.8.3  NEEDED: libc.so.6 · ld-linux
                          → 缺 libncursesw（就是那个 bug）

★ **这两组数把因果关系钉死了**：`bash` 能跑，是因为它自己链了 `ncursesw`；
  而那个共享库没有 —— 所以任何【动态】链它的东西（比如 python3 的 readline
  模块）都会在 `undefined symbol: UP` 上停住。

  ★ 而 `bash` 那句原来是【断言】，没有测量。测量之后它还多了一条信息：不是
    "bash 不需要 ncursesw"，而是"bash 自己链了它" —— 那才是为什么同一份坏的
    libreadline 能让 python3 挂而 bash 好好的。

★ 而这也说明了一件事：**"装上去"和"装对了"是两件事** —— 前者看包数，后者
要看那个包自己链了什么。

★★ 而"看链了什么"这件事，最省的办法是 `ldd -r`（`-r` = report unresolved
  symbols）。实测：1315 个 ELF 里它报了 41 个，而【真的只有一个】（就是
  libreadline）；另外 40 个是 bash 的 loadable builtin（符号由宿主 bash 注入）
  和一个 gdb 钩子（libthread_db）。见 `packages/docs/待办.md` §1.5.Bg。
