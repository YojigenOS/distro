# 决策记录（本仓库的部分）

**编号是全项目的，不是本仓库的。** 跳号表示那一篇在另一个仓库里。

```
本仓库   0001 库路径布局 · 0003 镜像命名与标签 · 0004 中文优先的含义
         0007 风味与交付形式 · 0008 开发循环与SSH · 0009 命名与品牌
         0012 中文优先的边界 · 0013 真机验证机与DD安装通道
         0016 二次元浓度与吉祥物

packages 0002 构建在容器内进行 · 0005 可复现构建与时间戳来源
         0006 包管理器选型与中文支持 · 0010 上游测试
         0011 构建环境的边界 · 0014 子包与拆分的时机 · 0015 许可
```

**分法是「它主要影响什么」**，不是主题。比如 0006（包管理器选型）两边都
相关，但它主要定的是**包的格式**，所以留在 packages 侧。

## 不可变

这里的正文【永远不改】——它们记的是当时决定时的事实。

所以里面的路径会过时（拆仓库之前，这些文件都在 `packages/` 下）。处理办法
是在标题下【追加】一行说明，不是回改正文。

## 为什么拆仓库时按这个分

15 篇里有 7 篇看起来"两边都相关"。但一篇一篇看下来，真正两边一样重的只有
两篇（0006 包管理器、0015 许可）——其余都有一个主要归属。

**与其为那两篇单独建一个跨仓库的决策记录仓库，不如就近放在主要归属那边。**
多一个仓库要多一次 clone、多一次跳转，而收益只是那两篇的位置好看一点。
