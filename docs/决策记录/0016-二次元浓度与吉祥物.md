# 0016 二次元浓度与吉祥物

- **日期**：2026-10-12
- **状态**：已决定（形象细节待定；**执行时机未到**——见文末「现在不做」）
- **影响范围**：版本代号的取值、镜像 tag、吉祥物这一份形象资产、`fastfetch` / `motd` /
  `firstboot` 这类"系统内露面点"、官网与发布公告的语气
- **关系**：**[0009](0009-命名与品牌.md) 的续篇**。0009 留了两个口子——「对外怎么说」
  和待定项「三个方向最终选哪个」。本文结掉后者，**并且和 0009 当时的倾向相反**。

## 从哪来

起因是一句话：

> 玩 Linux 的人，大多数都是程序员，而程序员又大多数都喜欢二次元。

这句话是**受众推导**，不是偏好。它和「由要求推出技术决策」是同一个动作：
先承认用户是谁，再决定系统长什么样。

`skirt`（建包）和 `pantsu`（建系统）就是这么来的。**它们不是彩蛋，是定位声明。**

## 一、二次元浓度和另外两条要求是同一个动作

| | 拒绝的是什么 |
|---|---|
| **中文优先** | 「默认用户是英语使用者」 |
| **二次元浓度** | 「品牌应当中性、无个性」 |
| **从零构建** | 「从别人的发行版起步」 |

三条指向同一件事：**不假装中立。**

主流发行版的名字都极力中立——Ubuntu 是非洲哲学、Fedora 是顶帽子、
Debian 是创始人夫妇的名字缩写——因为它们要同时面向全世界、企业、政府。
YojigenOS 反过来：**它不假装中立，它直接指定默认用户是谁。**

分寸由 [0004](0004-中文优先的含义与第一批动作.md) 那条管着，而且它管的不只是语言：

> **中文第一，英文可用，不把任何人挡在外面。**

二次元浓度第一，不懂的人也完全能用。**指定默认，但不排他。**

### 一个旁证（不是理由，是支持）

国际上的 Linux 折腾圈**已经**是二次元了——r/unixporn、NixOS 的猫娘、
Hyprland 的 ricing 文化、"I use Arch btw" 这一类。所以这不是往 Linux 里
"加"二次元，是**把既成事实说出来**。

中文侧的证据更硬：**bilibili 的名字来自御坂美琴的爱称「ビリビリ」。**
中国最大的 ACG 平台，用她命名的。

## 二、代号层：用动漫角色名

0009 那张表把「直接用动漫角色名」的代价写成**「名字不属于我们」**，
因此倾向日本神话/传说。**本文选第一行**，理由是浓度和受众指向：

| 选项 | 二次元浓度 | 受众指向 |
|---|---|---|
| **直接用动漫角色名** | 满 | ★ 直接命中 |
| 日本神话 / 传说 | 很足 | 要靠读者自己联想 |
| 原创少女名 | 取决于起得如何 | 要重新建立认知 |

而 0009 担心的风险，**它自己也给了出口**——Debian 从 1996 年起用
《玩具总动员》的角色名做代号，从没申请过授权，Pixar/迪士尼也从没追究。
关键是那三个字：**分寸**。

> 只用名字，不用角色形象、不用原画、不用字体、不拿它当产品名。
> **代号是技术性的，不是招牌。**

### 分寸落成分层

```
代号层    VERSION_CODENAME=misaka  ·  yojigenos/minimal:misaka
          ← 放开用。懂的人自己会撞见
招牌层    logo · 壁纸 · 开机画面 · 官网 · 宣传物料
          ← 不用别人的任何东西（见第三节：用我们自己的）
```

### 版权和商标是两件事，别混

这条 0009 已经分对了，照着用：

| | 能不能用 | 依据 |
|---|---|---|
| **名字** | ✅ 可以用在代号层 | 版权保护**表达**，不保护名字 |
| **形象**（原画、官图、官方字体） | ❌ 不能用 | 受版权保护 |
| **自己画的那个角色** | ❌ 也不能用 | 角色**设计**也是表达，自己画仍是派生作品 |

**所以"自己画一个御坂美琴"不是绕开办法**，它和直接用原画一样侵权。
名字能用，形象不能用——**无论谁画的。**

### 风险敞口（2026-10-12 查证）

- **没查到御坂美琴的商标注册记录**。公开搜索索引不到日本商标库，
  要确认得查 J-PlatPat。**这条是"没查到"，不是"没有"。**
- **但 KADOKAWA 确实把角色名注册成商标**：`キトラ` = 登录 6096070，
  类别含**第 9 类**（含电子计算机程序）。所以"角色名会被注册进软件类"
  是实证存在的，不能假设安全。
- 0009 那句「只要沾上捐赠或商业活动，就往上走一格」要记住——
  而 `packages/README.md` 的"现在不要做的事"里就躺着一个**赞助页**。

**结论**：现在是代号阶段，敞口很小。**在第一个正式版本发布之前查一次 J-PlatPat。**

## 三、招牌层：我们自己的吉祥物

招牌层不用别人的东西，用**我们自己的**。名字：

| | 用在哪 | 理由 |
|---|---|---|
| **次元娘** | 正式名 | 「娘」直接接上 **OS娘** 这个谱系 |
| **次元酱** | 日常称呼 | 更亲近，社区里会这么叫 |

这正是项目已经很熟的那个套路：**正式的那个给人读，日常的那个给人叫。**

### 她接上的是一个二十年的传统

ACG 拟人化操作系统，日本叫 **OS娘**——2003 年前后从 2channel 长出来的，
ME娘、98娘、2K娘、XP娘，Linux 那边也有 Tux 娘。

要紧的地方在于：**这不是我们的发明，是一条现成的谱系**，而且目标受众全都认识。
会去装一个从零构建的发行版的人，恰好就是最能读懂"操作系统拟人化"的那批人。

旁证：国内发行版的吉祥物基本是**瑞兽**系（麒麟那两个）或者干脆没有。
拟人化美少女在这条赛道上**没有先例——这是空位，不是跟风。**

### 她站位比想象中准

看 0009 那张三层表：

| | 是哪一层 |
|---|---|
| **YojigenOS** | 四次元的**系统**——最里面那个 |
| **四次元的空间** | 装这个系统的地方 |
| **`skirt`（短裙）** | 那个空间**外面的那层** |

`skirt` 是"外面那层"。那么一个穿短裙的次元娘是什么：

```
次元娘（人）        ← 你能看到的那个形象
  └─ 短裙          ← `skirt`，外面那层
      └─ 四次元空间  ← 你进不去
          └─ YojigenOS
```

**次元娘不是那个系统。她是外面那层。系统在她裙子里面。**

于是「不能随便看」这条原则不用解释就成立了——**你永远只能看到次元娘，
看不到系统。**（按 0009 的规矩标一句：**这是观察，不是比喻的含义。**）

### 形象方向

- 具有**企鹅要素**（Tux 那一路的血缘）
- **美少女**（OS娘 那一路的形式）
- **短裙系**

**企鹅要素建议放在穿戴而不是身体上**——企鹅连帽衫 / 企鹅玩偶 / 企鹅尾巴。
两个理由：

1. 太少看不出和 Linux 的关系，太多就变成 Tux 的衍生品
2. 连帽衫自带一层程序员味，比长翅膀更不容易滑向"兽娘"

### 配色不用另设计，企鹅白送一套

如果企鹅要素取 Tux 那套色——**黑、白、橙**（喙和脚）——配色是从吉祥物
身上长出来的，不是"设计"出来的：

```
黑   底色、深色 UI、终端背景
白   正文、留白
橙   唯一的强调色
```

黑 + 白 + 单一暖色高对比，正好也是"藏"的配色：**深底，少量亮，其余都在暗处。**

## 四、落点：藏在能被发现的地方

0009 说「中文那层意思，只有懂的人懂」。**二次元同理**：

> **浓度藏在能被发现的地方，不摆在会被看到的地方。**

| 落点 | 谁看得到 |
|---|---|
| **`fastfetch` / `neofetch` 的 ASCII art** | ★ 每次开终端都在，只有用终端的人 |
| `/etc/motd`、`yojigenos-firstboot` 的欢迎语 | 装系统的人 |
| 包管理器报错时的彩蛋 | 撞上的人 |
| 壁纸包（想装才装，不是默认） | 主动去装的人 |
| `VERSION_CODENAME` | 会去读 `os-release` 的人 |

这套落点**零风险、零成本、浓度精准命中**，而且天然筛人：
普通用户永远不会看到次元娘，程序员第一次开机就会撞见她。

## 未采用

- **角色名进招牌层**（logo / 壁纸 / 官网画那个角色）：撞版权，且撞 0009 的
  「不要往童趣的方向软化它」。
- **自画一个已有角色来绕开**：角色设计受版权保护，自画仍是派生作品。
- **日本神话方向**（0009 当时的倾向）：不是错，是浓度和指向性都弱一档。
  代号层改用它并不冲突，将来要换回来也不用改结构。

## 待定

- **迷你裙还是比基尼。** 原始表述是「迷你裙比基尼之类的」，没有定死。
  讨论中出现的一种意见（**未采纳为决定**）：迷你裙服务意象，比基尼拆意象——
  原点写的是「**不能随便看**，也不能随便摸」，力量在"藏"；比基尼是"都给你看"。
  另外它有一笔实际成本：会关掉几扇门（高校、企业采购、部分赞助、国内会议物料），
  **而门是慢慢关的，不会响。**
- **她是"官方看板娘"还是"系统的一部分"。** 差别很大：看板娘活在官网和发布公告里；
  系统的一部分活在 `fastfetch` / `motd` / 欢迎语里，是**系统自己的声音**。
  按「不能随便看」和第四节的落点，倾向后者。
- **她说不说话。** 会不会在 `motd` 里第一人称欢迎你——这会决定要不要给她
  写人格、语气、口头禅。**这一条定了，才谈得上形象设计。**
- 代号谱系怎么建（按时间？按作品？按主题？）。第一个正式发布才有代号。
- 企鹅要素的最终比例。

## 现在不做

**本文只记账，不动手。** 下面这些都有明确的时机，但不是现在：

- 次元娘的形象设计（立绘、三视图、表情）
- `fastfetch` / `motd` / `firstboot` 的落点实现
- 壁纸包
- 官网上的任何呈现
- 版本代号的实际启用（要等第一个正式发布）

理由和 `packages/README.md` 那节"现在不要做的事"一致：**先有能用的系统。**
