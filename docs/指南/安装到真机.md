# 安装到真机（DD 通道）

**目标机**：腾讯云 CVM `S5.LARGE4`，ap-guangzhou / ap-guangzhou-3，x86_64，
SeaBIOS（BIOS，**没有 UEFI**），40 GiB CLOUD_SSD，SSH 别名 `TX`。
**这台机器上没有任何数据，随便清空**（0013）。

通道本身为什么是 DD、为什么"我们不写安装器"，见 0013。这里是**动手的那一步**。

## 前置：缺一样都别开始

**1. 镜像已经在仓库里**（不是手边的文件）

```sh
curl -s https://repo.os.yojigen.cn/img/minimal/x86_64/latest.txt
```

拿不到就先让 CI 造一张：Actions →「**磁盘镜像**」→ x86_64 / minimal / 勾上发布。
（那张 workflow 会先**启动一次**再发布——没起来的镜像不会被推上去。）

**2. `reinstall.sh` 能下载**

GitHub raw 从广州只有 37 KB/s，用 cnb.cool 的镜像（实测 4 MB/s）：

```sh
curl -O https://cnb.cool/bin456789/reinstall/-/git/raw/main/reinstall.sh
```

✅ 已验证：这是**同一个文件**（5712 行），不是网页。
⚠️ 别用 `/-/raw/` 那个地址——它返回的是 CNB 的网页，不是文件本身。

**3. 镜像格式**

`dd --img` 支持 raw / vhd / tar / gz / xz / **zst**（它自己帮助的第 101 行）。
所以我们发布的那个 `.img.zst` 可以**直接**喂进去，不用先解压、不用先上传到别处。

## 退路：先确认它在，再动手

| 退路 | 怎么用 | 状态 |
|---|---|---|
| 控制台「重装系统」 | 腾讯云控制台点一下 | ✅ **实测**：40 秒把一台完全不可引导的机器（只剩 ESP、MBR 全 0）恢复成原样 Rocky |
| Alpine 只读环境 | `reinstall.sh alpine --hold 1` | ✅ **实测**：不碰磁盘、不留 `/reinstall.log` |

**第二条为什么留 1**：`--hold 1` 会让它在 trans 之前就退出——磁盘一个字节都不动。
所以它可以用来看"这个 live 环境是什么样"，而不会把你的机器变成别的系统。

## 做

```sh
ssh TX                 # 现在它是腾讯云的 Rocky

IMG=$(curl -s https://repo.os.yojigen.cn/img/minimal/x86_64/latest.txt)
URL="https://repo.os.yojigen.cn/img/minimal/x86_64/$IMG"
echo "要装的是 $IMG"
curl -sI "$URL" | head -3          # 先确认这个 URL 是通的

curl -O https://cnb.cool/bin456789/reinstall/-/git/raw/main/reinstall.sh
bash reinstall.sh dd --img "$URL"
```

它做的事：下载 → 边下边解 → 原样写 `/dev/vda` → 重启。

**它不会替我们改任何东西**——不加分区、不注入、不装引导器、
连 `resize_after_install_cloud_image` 都是被显式关掉的（0013 §一）。
所以镜像里必须什么都有：**这正是 `pantsu img` 存在的全部理由。**

## 看它起没起来

**从 VNC 看**（腾讯云控制台的 VNC 就是串口）。应该看到：

```
  ★ 欢迎来到 Yojigen OS
    内核     7.2.9
    架构     x86_64
```

看不到的话，按这个顺序查（每一层都有明确的症状）：

| 症状 | 大概是哪一层 |
|---|---|
| `Booting from Hard Disk...` 卡住不动 | 引导器没写进去——`boot.img` 不在 MBR、`core.img` 不在 bios_grub |
| `grub rescue>` | GRUB 起来了但找不到根——`root=PARTLABEL=` 对不对得上 |
| `Kernel panic ... VFS: Unable to mount root fs` | 文件系统或分区尺寸（"文件系统比分区大"就是这一类） |
| 内核起来了、但没有那句话 | `/init` 的问题（现在镜像里**没有 sshd**，只能从 VNC 进） |

## 装完之后仍然没解决的

★ 这一节 2026-10-15 逐条核过一遍——**原来那四条里有三条已经做完了**，
而剩下的那一条不是原来写的那件事。

- ~~SSH 公钥怎么进去~~ → **做了**。`openssh` 的 `files/ensure-authorized-keys`
  管这件事（`/root/.ssh/authorized_keys` 的存在、属主、权限，还管了升级那条路）。
- ~~盘上多出来的空间~~ → **做了**。`yojigen-os-init` 的 `files/10-grow-root`
  在首启时 growpart + resize2fs。
- ~~没有 sshd~~ → **做了**。`recipes/net/openssh` 在，`minimal` 也声明了它。
- **`grub` 仍然是从 Alpine 借的** —— 而原因和原来写的**不一样**：
  配方**已经建出来了**（`recipes/tool/grub`），**没做的是"换过去"那一步**。
  现在建盘时 `grub-mkstandalone` / `grub-install` 还是跑在借来的容器里，
  用的是人家的模块。要改的是把 `--directory` 指向我们自己包里的模块
  （`img.py` 的模块说明里写着"接口留好了，改的是一行"）。
  **所以这是一条真开着的活**，只是它的形状是"接线"，不是"写配方"。
