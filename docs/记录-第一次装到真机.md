# 第一次装到真机

**2026-10-13。** Yojigen OS 第一次跑在一台真实的服务器上——不是 QEMU，不是容器，
是一台腾讯云 CVM（`TX`，40 GB 盘、4 核、3.6 GiB 内存）。

**这是【记录】，不是【指南】。** 留在这里的原因是：**这一格和之前所有格都不一样**
——之前每一步都有产物，但每一步都是"我们自己的环境里验的"。

---

## 怎么装的

```
reinstall.sh dd --img https://repo.os.yojigen.cn/img/minimal/x86_64/…img.zst
```

它做的事：引导进一个内存里的临时 Linux，把 53 MB 的镜像写到 `/dev/vda`，重启。

**装完之后，那台机器就是我们的了** —— 不是"装了个 Yojigen 的软件"，是
**整台机器从上游源码建出来的**。

## 起来之后的样子

```
NAME="Yojigen OS"
HOME_URL="https://os.yojigen.cn"

根分区      38G（镜像里只有 509 MiB，起来自己撑满）      ← 首启钩子 10-grow-root
网络        默认路由 via 10.1.0.1（DHCP）               ← 首启钩子 15-network
sshd        起来了，作者的公钥能登进去，有交互终端        ← 首启钩子 20-sshd
apk         能 update，能从自己的仓库装包，装完能跑        ← 70 个包

内核 7.2.9 · /init · GRUB · apk · openssh —— 全是自己建的
```

一句话：**它自己把自己装上去，然后自己配置好自己。**

## 三个只在真机上才露出来的问题

### ① root 在 `/etc/shadow` 里是锁定的 → sshd 拒绝一切认证

```
root@…: Permission denied (publickey,password,keyboard-interactive)
```

而 `/root/.ssh/authorized_keys` 里公钥在、权限 600/700 全对、sshd 配置也对。

原因在那句注释里：

```
# 没有密码（!），root 只能通过提权或直接访问进入。
# 这是给【容器基础镜像】用的合理默认值；真机上【安装器会设置 root 密码】。
root:!::0:::::
```

**而 DD 通道没有安装器** —— 没有任何东西会去解开 root。

**这是"某样东西按 A 场景配的，被用在 B 场景"** —— 而两个场景的期待不一样。

### ② `/root` 的属主是构建用户，不是 root → StrictModes 拒绝

```
/root:  runner:runner 700
```

模式 700 对，属主不对。

**同一类问题的第三次**：

```
/var/empty        模式 711 对，属主不对   → sshd 起不来
authorized_keys   内容对、0600 对，属主不对 → 钥匙被拒
/root             内容对、0700 对，属主不对 → 钥匙被拒
```

★ **sshd 检查的从来不只是内容，也不只是模式 —— 是 mode 和 ownership 两样。**

### ③ `/dev/pts` 没挂上 → SSH 拿不到终端

```
PTY allocation request failed on channel 0
```

`/init` 里那句：

```sh
mount -t devpts devpts /dev/pts 2>/dev/null
```

**失败了，而 `2>/dev/null` 把它藏了起来。** 因为 `devtmpfs` 不建 `/dev/pts`
那个目录，往不存在的目录上 mount 会失败。

后果不是"少挂一个文件系统"，是 **SSH 上来敲什么都没反应**。

★ **原因和症状隔了好几层** —— 这是这类错误最贵的部分。

## 为什么 CI 一个都没挡住

因为**没有一个测试真的"用它"**：

```
CI 验的                            真机发生的
──────────────────────────       ──────────────────────────
"sshd 说它自己启动了"          →   钥匙被拒
"脚本挂在 /usr/lib/.../boot.d" →   /root 的属主不对
"文件按 711 建好了"            →   属主不是 root
```

**每一条都是"它说自己没问题"，而不是"我用它做了件事，成了"。**

补的验收也是照着这个方向：

```
apk 能装软件       →  chroot 进去真的装一个包，再跑它
DHCP 拿到地址      →  等它真的拿到地址
SSH 登得进去       →  真的 ssh 一次（这条还在修）
```

## 一个副作用

装完之后发生了一件荒唐事：**换成我们自己的系统之后，反而装不了自己了** ✗

因为 `reinstall.sh` 要靠 `curl` 下载救援环境 —— 而我们的系统里**没有 curl**
（apk 有自己的 HTTP 客户端，但那覆盖的只是 apk 的用法）。

于是第一次装得进去（那时机器还是 Rocky，Rocky 有 curl），第二次装不进去了。

**这不是"少个小工具"，是一个能自举的系统必须具备的能力：它得能从网上取东西。**
`curl` 包当天补上了。
